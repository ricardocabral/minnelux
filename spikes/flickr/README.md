# Flickr reconciliation spike

Run `node --test spikes/flickr/reconcile.test.mjs` from the repository root. The reconciliation module uses browser APIs and accepts a part's parsed sidecars, album records, and original `Blob`s. Each part has a stable ID so replaying it does not create new candidates. The returned preview and state can be passed to the next import.

The fixture has two metadata parts and two media parts. It includes an EXIF Orientation 6 JPEG and an H.264 MP4 with a `.jpg` export name to exercise signature detection. Both originals were generated from FFmpeg's `testsrc2`. The sidecars and album records are synthetic. Run `node spikes/flickr/pack-fixture.mjs` with `zip` on `PATH` to generate four standalone ZIPs in a new temporary directory. The command prints the directory path.

Album documents can arrive after sidecars. The spike records sidecar-only album edges as provisional and withdraws them when the authoritative list disagrees. The applied-membership history makes retries honor owner removals while allowing newly discovered edges. The spike keeps raw source records and original bytes alongside normalized fields.

The tests exercise all 24 arrival orders, an album conflict, a pending member, source account isolation, and ambiguous or duplicate files. They replay a part after restoring the state from JSON and separately stored original bytes. A later duplicate or conflict stays visible in the preview while the previously linked asset, original, and owner edits survive. A collision between candidates without an existing link stays unresolved.

On November 18, 2026, all six tests passed in Node 26.13.1. In a separate smoke run, `unzip` verified and unpacked all four generated archives with 3, 1, 1, and 1 members. Headless Chromium 159.0.8154.6 reconciled the parsed parts in media-first order, matched two originals, and kept one pending record. A fresh page restored the JSON and original bytes, replayed a part, and detected one late byte-identical duplicate. Both assets and the edited title survived, and the removed tag stayed absent. Browser ZIP extraction, durable cloud publication, and composing EXIF orientation with Flickr rotation at preview time remain follow-up checks.
