# Minnelux web client architecture

**Decision for this implementation draft** · November 18, 2026

Build the archive client as a static HTTPS single-page app using React 19, strict TypeScript, and Vite. Keep library semantics independent of React. Run catalog and search work in a dedicated worker, start a second worker for expensive import work on demand, and use a service worker for private video ranges. The owner's bucket is the durable record. Keep the authorized browser working set in memory.

[Product requirements and release criteria](../../prod/minnelux-prd.md) · [Implementation plan](../../../plans/web-client.md)

## Framework decision

| Choice | Finding |
| --- | --- |
| **React 19 + Vite** | Selected for its established, compatible tooling for a static SPA, a virtualized gallery, accessible controls, and Hooks diagnostics. Its main risk here is placing job and resource lifecycles in component effects. Keep those lifecycles in testable session, library, and worker modules. [React and Vite](https://react.dev/learn/build-a-react-app-from-scratch) · [Hooks lint rules](https://react.dev/reference/eslint-plugin-react-hooks) |
| **Vue 3 + Vite** | A viable choice with official routing and devtools and documented large-list patterns. Workers, adapters, and file formats would use the same contracts. [Vue quick start](https://vuejs.org/guide/quick-start.html) · [Vue performance](https://vuejs.org/guide/best-practices/performance.html) |
| **Solid 2 + Vite** | Solid 2 is stable. Its async reactivity and development diagnostics give agents actionable feedback with error codes and source locations. The TanStack Solid Virtual manifest inspected on November 18 declared a Solid 1 peer dependency. A Solid trial would need a verified virtualizer and accessible viewer. Compare maintenance on the same fixture with stale-search and focus-restoration tasks if the project reopens the framework decision. [Solid 2 announcement](https://www.solidjs.com/blog/solid-2-0-the-long-hold/) · [Example diagnostic](https://docs.solidjs.com/reference/solid-js/diagnostics/strict-read-untracked/) · [Virtualizer manifest](https://github.com/TanStack/virtual/blob/main/packages/solid-virtual/package.json) |

There is no Minnelux framework bake-off behind this decision. The ProductWebBench preprint, reviewed November 18, measured a confirmed regression in 107 of 586 completed change runs with baseline and checkpoint coverage. Its framework groups used different projects and tasks. Use the finding to prioritize repeatable regression tests for agent changes. [ProductWebBench, Table 4 and Appendix F](https://arxiv.org/html/2610.31118v1)

## Runtime ownership

| Runtime | Owns | Provides to callers |
| --- | --- | --- |
| **Window and React** | Connection and provider sign-in, a session controller, route and interaction state, preview and full-size image presentation, authorized video registration. | Commands and small immutable session or job snapshots. The gallery receives result counts and visible records. |
| **Library worker** | The authorized repository, pinned revisions, catalog, text and tag postings, ordered result sets, reads, publication, and index repair. | Revision-bound queries, row ranges, viewer navigation, import base reads, and explicit publication outcomes. |
| **Import worker** | On-demand ZIP parsing, matching and planning, incremental hashing, and bounded preview work where browser APIs support it. | Plans, progress, diagnostics by code, and repeatable byte reads for the current job. Use a bounded window-side media decode fallback where needed. |
| **Video service worker** | The same-origin video fetch route, requesting-client verification, and authenticated range validation and streaming. | A tab-bound video URL. The authorized window can resolve a live registration again after the worker restarts. |
| **Object storage** | Originals, previews, raw source records, catalog and index snapshots, manifests, operation receipts, and the conditional head. | Durable state that a fresh authorized browser can reopen. |

Use React Router in declarative hash mode for generic routes such as `#/connect`, `#/library`, `#/import`, and `#/viewer`. The current asset, collection, raw query, and scroll or focus anchor live in memory. Opening the viewer adds a navigation entry. Back or closing the viewer restores the pinned view and returns focus to its asset when available. A direct viewer route without an active result set goes to the library or connection screen. Use TanStack Virtual for gallery ranges, React Aria Components for controls and dialogs, and native image and video elements. Check keyboard navigation, focus, readable loading states, and live import progress in the browser. Subscribe to small external snapshots using `useSyncExternalStore` where state spans features. [HashRouter](https://reactrouter.com/api/declarative-routers/HashRouter) · [TanStack Virtual](https://tanstack.com/virtual/latest/docs/framework/react/react-virtual) · [React Aria](https://react-aria.adobe.com/Modal) · [React external store API](https://react.dev/reference/react/useSyncExternalStore)

Use Vite module workers for library and import work. Emit the video service worker as a separate entry at a stable URL under the app's deployment base. Register it with scope over the app document and intercept only the video path within that base. The deployed build must support same-origin worker loading and provider callbacks at their configured paths. Lazy-load the active provider and the importer. Serve static assets with the PRD's HTTPS and response-header policy. [Vite workers](https://vite.dev/guide/features.html#web-workers) · [PRD security requirements](../../prod/minnelux-prd.md#security-requirements)

## Contracts shared by implementers

### Session and worker messages

- Bind each session to a provider identity, approved endpoints, library prefix, optional media root, and effective read or edit capability. The window's session controller owns renewal and lifetime. Give a worker only the credentials or scoped access it needs. Credential material can exist in authorized runtimes for the active session and stays out of React state and diagnostics.
- Give each session binding a fresh identifier. On expiry, disconnect, or identity or library switch, abort obsolete requests, invalidate registrations and worker results, clear private UI and memory caches, and revoke object URLs. When reauthorization is offered, keep only the in-memory information needed to verify the same identity, library, and asset before resuming playback, or the same identity and library before reconciling a publication. Explicit disconnect or switching discards that recovery context.
- Use typed request and response unions over native messages. Carry a protocol version, session ID, and request ID. Carry the revision or result handle for revision-dependent reads. Replies contain a result, progress, or a coded error. Cancellation targets a request or job ID and aborts worker-side work. The receiver validates the envelope and ignores replies outside the active binding or query. An incompatible page and service-worker build fails closed and surfaces a reload path.
- Keep query handles tied to a revision. A result includes its handle and total count. A subsequent range includes the handle, offset, and limit and returns ordered display records. The viewer can request neighboring assets from the same list. Release handles when neither the gallery nor viewer needs them. Pin only the working sets required for active views and jobs.

Reauthorization requires provider identity evidence tied to the new credentials. Verify in the provider proof that the subject is stable on renewal and changes when the account changes. For GCS, test an OpenID Connect subject from UserInfo using the same GIS OAuth grant before any token downscoping. For S3, use the configured identity pool and authenticated Cognito identity ID that issued the temporary credentials. For Azure, use the tenant and object ID from the MSAL account used to obtain the Storage token. For R2, require the external credential issuer to bind a stable issuer and subject to the temporary credentials. For configurations without comparable identity evidence, open a new session and require the user to reopen the asset or rediscover the operation in the published library. Bucket access by itself proves authorization to the bucket. [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect#obtainuserinfo) · [Cognito identity IDs](https://docs.aws.amazon.com/cognitoidentity/latest/APIReference/API_GetId.html) · [Entra ID token claims](https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference) · [R2 temporary credentials](https://developers.cloudflare.com/r2/api/s3/temporary-credentials/)

### Provider storage adapter

One adapter instance operates on an authorized library and media root. Use the provider-specific auth, CORS, and conditional-write rules in the PRD. Reuse the GCS transport and S3 signing and identity proofs as inputs. Each adapter runs the same observable contract cases. [Provider requirements](../../prod/minnelux-prd.md#storage-providers-and-authentication) · [GCS proof](../../../spikes/gcs/README.md) · [S3 proof at the source revision](https://github.com/ricardocabral/minnelux/tree/b3d0b33/spikes/s3)

| Capability | Contract |
| --- | --- |
| Paginated list and metadata | Return provider-relative keys, a continuation cursor, and available object metadata. Check authorized roots and encode keys exactly at the provider boundary. Preserve provider versions as opaque values. |
| Full and range reads | Provide a byte stream and readable status, lengths, type, and range information. Distinguish confirmed absence, denial, expiry, and transport failures when the provider exposes them. |
| Current head | Return the body bytes and opaque write condition from the same read. Represent confirmed absence separately. A provider denial or ambiguous error cannot initialize a library. |
| Immutable upload and head update | Use create-only writes for immutable objects, verify existing objects before reuse, and condition the head update on the observed head token or confirmed absence. Return a stale precondition separately from an uncertain outcome. Keep resumable upload credentials in memory. |

### Repository, indexing, and imports

- Use the existing versioned object layout and portable relative references. Start with whole gzip snapshots for the catalog, text postings, and tag postings. Validate encoded and expanded sizes, hashes, schemas, versions, and posting ordinals before use. Search uses the published index and the PRD's ranking and normalization. Missing, incompatible, or corrupt postings leave the catalog available and enable explicit index repair.
- Read valid v1 Flickr importer revisions and emit a v2 manifest for new publications. The v2 manifest supports receipts for general library operations as well as Flickr operations scoped to a source. Keep the v1 identities, source state, retained receipts, and media references on the first successful conditional write. That write appends a revision and leaves previous objects intact. Version the head and each snapshot independently and retain encodings that remain compatible. Freeze the generated v1 input and expected v2 output with the shared contracts. Verify the round-trip when the repository implements conditional publication. [Importer manifest implementation](../../../apps/flickr-import/repository.mjs) · [GCS repository task](../../../plans/gcs-reference-workflow.md#task-3--revision-repository-and-publication)
- The library repository is the only publisher. It writes immutable objects, snapshots, and the manifest before attempting the conditional head update. For an interrupted update, reconcile with the current head and a receipt for the same operation and intent. Expose a possibly committed outcome explicitly. A stale base or a missing receipt alone cannot settle an ambiguous outcome. Apply independent edits to a fresh base and surface overlapping field changes for resolution.
- An import reads its pinned base, previews a plan, and submits the confirmed plan to the same publisher as owner edits. The existing Flickr contract governs source identity, candidate and raw-record preservation, membership precedence, owner overrides, and retry semantics. Preserve asset IDs and original bytes. Reuse suitable parser, planner, preview, and repository code from the standalone importer. Exercise its emitted revisions as compatibility fixtures. [Flickr specification](../flickr-import/SPEC.md) · [Flickr repository contract](../flickr-import/REPOSITORY-CONTRACT.md) · [Importer implementation](../../../apps/flickr-import/README.md)
- Send `File` objects to the import worker and do bounded reads there. Keep byte-opening functions in their owning runtime. Pass byte handles or transferable streams through the worker interface, with a pull-based transferable-chunk fallback where needed. Bound byte, entry, dimension, and concurrency budgets. Use provider resumable uploads or multipart operations for large files. Published import state survives a fresh session. Ask for ZIP or file reselection when an unpublished byte source is required. [Browser File API](https://www.w3.org/TR/FileAPI/) · [Transferable streams](https://streams.spec.whatwg.org/#rs-transfer)

### Photo and album details

Read optional details from the pinned catalog through the library worker as part of the selected photo or album response. The [storage field reference](../storage/SPEC.md#optional-photo-and-album-fields-in-catalog-v1) defines the available values. Use the existing session and pin checks for these responses. Render available details and omit absent sections, including for catalogs written before these fields were added.

- Show the photo's license and source page, comments and annotation text with available authors and timestamps, group memberships, and historical tag authors. Keep source tag authorship distinct from the photo's current tags. Display annotation geometry only when the original coordinate space and orientation can be mapped to the displayed image.
- Show JPEG EXIF camera, lens, shooting settings, and timestamps, plus IPTC caption and dates when saved. Label embedded values separately from the photo's main capture date. Preserve the recorded wall time where the offset is absent.
- Show the album's description, cover, and creation and update dates. Resolve the cover photo ID against the same Flickr source in the pinned catalog and load its stored preview through the authorized media adapter. If a preview cannot be resolved, leave the image empty and offer the saved cover link when present.
- Render imported strings as plain text. Treat source URLs as explicit links, using only credential-free HTTPS URLs. The gallery and details view never load remote source URLs for previews.

### Media and browser storage

- Resolve previews and images through the active adapter. Fetch and decode visible previews with bounded concurrency and discard stale work as the visible range changes. Allocate and revoke object URLs with their consumers. Fetch originals on demand. Untrusted import text renders as text and unsupported formats retain a download path.
- Register each video under an opaque route ID tied to the current client, live session, library, and authorized asset. On each range request, the service worker checks the requesting WindowClient and asks only that client for the registration through a message port. Missing, mismatched, expired, or incompatible state denies the request. Use the authorized adapter to fetch the range and stream a validated `206` with the required range headers and `Cache-Control: no-store`. Bound requests and reject upstream responses that ignore the range or disagree on type, length, or offsets. Abort in-flight reads on invalidation. Resume the same asset after reauthorization only after checking the binding again. [PRD private media delivery](../../prod/minnelux-prd.md#private-media-delivery) · [Service worker lifecycle](https://www.w3.org/TR/service-workers/#service-worker-lifetime)
- Persist only non-secret connection settings in the browser. Keep private data, credentials, and presigned or resumable upload URLs out of app-managed persistent stores, browser history, and logs. Limit diagnostic data to event names, timings, phase, error codes, and run-local correlation IDs. Use synthetic private data in traces and fixtures.
- Defer IndexedDB and OPFS for the first release. If repeat-open transfer or memory misses the target, measure which stage dominates and test catalog pages or posting shards as appropriate. Consider Dexie for a bounded, disposable revision-keyed cache only with a product decision changing session-only storage behavior. Consider SQLite WASM with OPFS only for a measured disk-backed indexing or SQL need. Verify browser eviction, Safari, multiple tabs, and provider popup compatibility before adopting the selected mode. [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/) · [SQLite persistence modes](https://sqlite.org/wasm/doc/trunk/persistence.md)

## Verification targets

The existing higher-vocabulary benchmark, recorded November 18, 2026 at 13:10 BRT, used 50,000 generated assets, headless Chrome on macOS, 20 Mbps and 80 ms modeled loopback, and 40 samples per stage. Its p95 was 1,599.4 ms to reopen and order the first page, 645.3 ms for cold search, and 7.0 ms for warm search. The release measurements include visible thumbnails, real provider transport, and peak memory on the target phone. [Snapshot benchmark workload and measurements](../../../spikes/snapshots/README.md)

- **Contract tests.** Keep the existing Node tests. Exercise publication with two sessions, a deliberately lost successful head response, stale and corrupted snapshots, import replay with owner edits, and account or library switches. Use synthetic media and a test object endpoint that implements the actual precondition and range behaviors.
- **Browser tests.** Run Playwright against the built app with real workers across Chromium, Firefox, and WebKit. Retain failure traces for synthetic fixtures. Check private video on desktop Safari and a physical iPhone, including provider login, seeking before download completes, worker restart, expiry, and replay denial. Run the same deployed workflow on real private buckets for each supported provider. [Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer) · [Playwright browser coverage](https://playwright.dev/docs/browsers#webkit)
- **Performance.** On a midrange mobile device using a real GCS bucket, the representative 50,000-item fixture, and a 20 Mbps / 80 ms link, target p95 of 3 s from authorized open to visible thumbnails, 1 s from a cold text query to rendered results once the catalog is ready, and 250 ms for warm text search. Record fixture profile, device, browser, sample size, timestamps, bytes, request counts, and peak memory. Time index build, snapshot compression, and publication separately. [PRD release validation](../../prod/minnelux-prd.md#6-release-validation-and-implementation-order)
